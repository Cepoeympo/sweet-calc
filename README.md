# Sweet Calc

Офлайн-приложение (PWA) для домашней кондитерской: себестоимость, техкарты, пропорции замеса и КБЖУ
зефира, мармелада, безе, пастилы, конфет и десертов.

Все данные хранятся локально в браузере устройства (IndexedDB) и не отправляются на сервер.
Приложение работает без интернета после первого открытия.

## Возможности

- **Калькулятор заказа** — расчёт по штукам или по весу, комплектация упаковкой и расходниками,
  наценка, округление цены, прибыль, КБЖУ на 100 г и на заказ, копирование текста для клиента.
- **Продукция** — техкарты с фото 512×512 или заглушкой, себестоимость за 100 г и за штуку,
  режим «Замес» с пересчётом граммовок на нужную партию, дублирование рецепта.
- **Склад** — продукты в граммах, штучная упаковка, накладные расходы (фикс. сумма или процент),
  дата последнего обновления цены, справочник КБЖУ с автоподстановкой. При первом запуске
  склад предзаполняется 9 позициями упаковки и всеми 104 ингредиентами справочника с ценой 0 ₽.
- **Настройки** — системная/светлая/тёмная тема, 8 акцентных палитр, наценка и шаг округления,
  экспорт/импорт JSON, синхронизация через GitHub Gist, история версий.

## Стек

React 18 + TypeScript, Vite 5, Tailwind CSS 3, `lucide-react`, `react-easy-crop`, `idb`,
`vite-plugin-pwa`. Тесты — `vitest`.

## Как считаются деньги и КБЖУ

Единый источник формул — модули [`src/lib/calc.ts`](src/lib/calc.ts:1),
[`src/lib/nutrition.ts`](src/lib/nutrition.ts:1) и [`src/lib/scale.ts`](src/lib/scale.ts:1).
UI не выполняет собственных вычислений, а только отображает результаты этих функций.

- `unitPrice` = цена упаковки / вес (количество) упаковки; для накладных — сама сумма.
- `batchCost` = Σ `amount × unitPrice` по ингредиентам партии.
- `costPerGram` = `batchCost / finalWeight`, `costPerPiece` = `batchCost / finalPieces`.
- `nutritionPer100g` = (Σ КБЖУ ингредиентов партии / фактический вес партии) × 100 — так
  учитывается уварка и усушка. Незаполненные поля КБЖУ считаются нулём.
- Цена заказа = `(себестоимость продукции + упаковка и расходы) × (1 + наценка / 100)`,
  затем **округление вверх** до выбранного шага (10/50/100 ₽), чтобы не терять прибыль.

## Данные и приватность

- Хранилище: IndexedDB `sweet-calc` (склад, рецепты, настройки, сжатые фотографии).
- Резервная копия — JSON-файл `sweet-calc-backup-YYYY-MM-DD.json`; токен GitHub в файл не попадает.
- Токен GitHub Gist хранится только в IndexedDB устройства. Не коммитьте его в репозиторий.
- Режимы импорта: «Заменить текущую базу» и «Добавить недостающие» (по идентификаторам).

## Справочник КБЖУ

[`src/data/nutritionPresets.ts`](src/data/nutritionPresets.ts:1) — 104 позиции на 100 г
(сахара и подсластители, желирующие и загустители, яичные и молочные, фрукты и пюре,
шоколад, орехи, какао, мука, специи). Значения ориентировочные, пользователь может изменить
их или оставить пустыми.

Данные сверяются автоматически: `npm run audit:nutrition` пересчитывает калорийность по формуле
Атуотера (белки 4 · жиры 9 · углеводы 4 ккал/г) и печатает расхождения. Остаточные расхождения
физически объяснимы:

- **клетчатка** (какао-порошок, корица, агар-агар, камеди) даёт ~2 ккал/г вместо 4;
- **полиолы** (эритрит, изомальт, ксилит, сорбит) — 0–2,6 ккал/г;
- **спиртовые экстракты** (ванильный) — 7 ккал/г;
- **органические кислоты** (лимонный сок) и разрыхлитель учитываются по официальным таблицам.

Отдельно про **агар-агар**: в исходном задании указано «900», но это сила геля в г/см²
(характеристика желирующей способности), а не калорийность. Пищевая ценность сухого агар-агара —
**306 ккал, Б 6,2 · Ж 0,3 · У 80,9 на 100 г** (USDA). Именно эти значения и стоят в справочнике.
