# Правила разработки Sweet Calc

## Архитектура

- **Расчёты только в `src/lib`.** `calc.ts` (себестоимость, заказ, округление), `nutrition.ts`
  (КБЖУ), `scale.ts` (пересчёт замеса), `format.ts` (форматирование). Компоненты не выполняют
  собственной арифметики — иначе цифры на разных экранах разойдутся.
- **Слой данных — `src/db`.** `index.ts` описывает схему IndexedDB (v1: `stock`, `recipes`,
  `settings`, `meta`), `repo.ts` — единственное место с CRUD и сидами. Компоненты не обращаются
  к `idb` напрямую.
- **Состояние — `src/store`.** `AppProvider` загружает базу один раз, держит `stock`, `recipes`,
  `settings` и `stockMap`, отдаёт действия и тосты. Экраны используют `useApp()`.
- **Тема — `src/theme/theme.ts`.** Тема и акцент применяются через класс `dark` и CSS-переменные
  `--accent`, `--accent-soft`, `--accent-foreground`; `meta[name="theme-color"]` обновляется там же.
- **Экраны — `src/features/<домен>`**, общие компоненты — `src/components`, примитивы —
  `src/components/ui`.

## Инварианты, которые нельзя ломать

1. `base` в Vite — `/sweet-calc/`; манифест использует `start_url`/`scope` `/sweet-calc/`.
   Ассеты из `public` подключаются только через `%BASE_URL%` или `import.meta.env.BASE_URL`.
2. Все поля `<input>`, `<textarea>`, `<select>` не меньше 16px (защита от автозума iOS);
   числовые — `inputMode="decimal"` (компонент `NumberField`).
3. КБЖУ-поля необязательны: `undefined` в расчёте равно `0`, но отсутствие данных должно
   отображаться как «КБЖУ не заполнено», а не как нули.
4. Токен GitHub Gist никогда не попадает в код, логи, экспортируемый JSON и Git.
5. Фото рецепта: кроп 1:1 через Canvas в 512×512, `imageSmoothingQuality = 'high'`,
   WebP 0.85 с фоллбэком в JPEG.
6. Цены округляются **вверх** до шага настройки (`roundPriceUp`).
7. Все изменения формул сопровождаются тестами в `src/lib/__tests__`.

## Проверки перед завершением задачи

```bash
npm run lint
npm run typecheck
npm run test
npm run build
npm run preview   # smoke-тест вручную
```

Проверка считается выполненной только при фактическом запуске команды и нулевом коде возврата.

## Работа с Git и данными

- Перед изменениями смотреть `git status` и `git diff`, не перезаписывать чужие правки.
- Коммит, пуш и деплой — только по отдельному разрешению пользователя.
- Не удалять пользовательские данные и не сбрасывать историю Git.
